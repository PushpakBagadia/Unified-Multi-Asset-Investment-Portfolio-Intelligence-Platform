4. PHASE 1 — YAHOO FINANCE INTEGRATION (BACKEND)
--------------------------------------------------
Built a provider-layer architecture so the app isn't tied directly to
yahoo-finance2 — a future data source (e.g. Upstox) can be swapped in later
without touching controllers or the frontend:

    Controller → MarketService → YahooProvider

Files created:
- backend/src/services/market/providers/yahooProvider.js
  Wraps the yahoo-finance2 library. Handles:
    - search(query)        — stock/fund symbol search
    - getQuote(symbol)      — live price, change %, volume, market cap
    - getChart(symbol, ..)  — historical candles (had to translate a "range"
                              string like "1mo" into period1/period2 dates,
                              since yahoo-finance2 v4's chart() requires exact
                              dates, not a range shortcut)
    - getIndices()          — NIFTY 50, SENSEX, BANK NIFTY live quotes
- backend/src/services/market/marketService.js — thin pass-through to the
  active provider (currently yahooProvider).
- backend/src/controllers/marketController.js — request/response handling
  for each endpoint.
- backend/src/routes/marketRoutes.js — route wiring.
- Mounted at /api/market in backend/src/app.js.

Endpoints (all tested and working):
    GET /api/market/search?q=reliance
    GET /api/market/quote/RELIANCE.NS
    GET /api/market/chart/RELIANCE.NS
    GET /api/market/indices

Note: yahoo-finance2 installed as v4, which changed its API from a plain
export to a class you instantiate (`new YahooFinance()`) — the provider
was adapted accordingly.


5. CONNECTING THE FRONTEND TO THE BACKEND
--------------------------------------------
- Installed and wired up `cors` middleware in backend/src/app.js
  (`app.use(cors())`) — without it, the browser blocked every request from
  the frontend (localhost:5173/5174) to the backend (localhost:5000) with a
  CORS error.
- Added frontend service functions (frontend/api/services.js) and endpoint
  paths (frontend/api/endpoints.js) for: searchStocks, getStockQuote,
  getStockChart, getMarketIndices.


6. LIVE STOCK SEARCH — GLOBAL NAVBAR
----------------------------------------
- The navbar search box (id="global-search-input") previously only searched
  a hardcoded mock array (state.fundsCatalog). It now ALSO calls the backend
  /api/market/search endpoint in parallel and shows real, live stock results
  in a separate "Live Stocks" section of the dropdown.
- Fixed a bug in the original implementation where a stale "No results
  found" message never got removed once live results arrived (the code was
  checking the wrong DOM attribute).
- Redesigned the dropdown's visual styling from scratch — it had literally
  no CSS rules defined for its result items before (unstyled divs). Added:
  section labels ("Mutual Funds & More" / "Live Stocks"), a loading state
  ("Searching live stocks…"), hover highlighting, and a proper empty state.


7. INVEST PAGE — EQUITIES TAB NOW SHOWS ONLY REAL DATA
----------------------------------------------------------
- Previously the "Equities (Direct Stock)" tab on the Invest page showed 2
  hardcoded mock entries (Tata Motors, Reliance). These were removed.
- Added a dedicated search box on that tab. Typing a company/symbol now
  fetches live search results AND live quotes from the backend, rendering
  real price + day-change % cards. An empty state prompts you to search
  when the tab first opens.
- Clicking a live stock result in the navbar dropdown now jumps straight to
  this tab, auto-fills the symbol, and triggers the same live search —
  i.e. clicking a stock takes you to the correct type-specific view.


8. STOCK LOGOS
----------------
- First attempt: Clearbit Logo API (guessing a company's domain from its
  name). This technically worked in code, but real-world testing showed
  Clearbit is blocked by Firefox's built-in tracking protection (and many
  ad-blockers), so most users would silently see zero logos.
- Switched to Financial Modeling Prep's public logo-by-ticker endpoint
  (financialmodelingprep.com/image-stock/{SYMBOL}.png), which doesn't
  require guessing a domain and isn't on tracker blocklists. Confirmed
  working for real stocks (e.g. TCS, HDFC Bank); correctly falls back to a
  colored-initials avatar for tickers/mutual-fund codes with no logo
  (invalid image data triggers the <img> element's onerror handler).


9. CLICKING A STOCK NOW LEADS TO A FULL BUY FLOW
----------------------------------------------------
- Stock result cards on the Equities tab now have an "Invest Now" button.
- Clicking it opens the same checkout modal used for mock mutual funds, but
  adapted to show the stock's real live price and day change instead of a
  fake "1Y Yield".
- Confirming a purchase creates a holding using the REAL live price (previously
  every mock fund purchase used a hardcoded dummy price of ₹120 regardless of
  the asset — stocks now use their actual price for unit calculation).
- Holdings are now matched/accumulated by ticker symbol for stocks (to avoid
  collisions from 2-letter initials, e.g. two different stocks both starting
  "TC"), while mock funds keep their original initials-based matching.
- NOTE: This purchase flow is still entirely simulated client-side state
  (same as it always was for mock mutual funds/gold/FD) — there is no real
  backend order-execution or persistence to MongoDB yet. A refresh will lose
  any simulated holdings, same as before this session's changes.
